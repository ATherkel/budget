Import identity and merge: prototype of PR #16's rules

The question. Do ADR-009/ADR-010's import-identity and merge rules give stable transaction IDs and the same set of transactions no matter how a household actually imports its exports, and where exactly do they break?

This is version 2. Run against PR #16 as written (5076f70), all 17 of issue #5's scenarios passed but every one of the review's seven claims reproduced. The defaults below are now the proposed fixes, which this branch also writes into the ADRs and the layer documents; each claim tab compares PR #16 as written (left) with the fix (right), and every switch still offers the old reading.

The compare view runs one scenario under two rule sets side by side and highlights what differs (transactions, IDs, run status, review items, per-month coverage, provisional labels). Every state is rebuilt from the import runs, so nothing is stored anywhere; reloading the page starts over. README.md next to this file is a plain-language walkthrough.

Built-in walkthroughs use made-up data. Real or tweaked exports come in through Free play → import a file. They stay in this browser tab. Filenames are shown with long digit runs masked.
