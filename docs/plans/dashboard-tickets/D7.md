# D7: Deliver accessible actual-versus-budget trends and spending drill-down

Part of: https://github.com/ATherkel/budget/issues/100. First-release delivery plan.

Blocked by: #101, #104, #107

## Problem Statement

Expose time patterns and budget comparisons without duplicating aggregation or relying on a mouse-only chart.

## Solution

Overall and scoped trends work at phone/desktop widths and pass report, rendered-response and interaction checks.

## User Stories

1. As a reader, I want actual-versus-budget trends, so that I can see how spending changes over months.
2. As a reader, I want the agreed group/category selection, so that I can investigate one spending heading.
3. As a reader, I want exact tabular values and truthful gaps, so that chart geometry is not the only explanation.

## Implementation Decisions

- Implement analytics trend reports for overall income/expenses/net and expense budget, and the accepted Category-group/Category selection.
- Both groups and individual Categories are confirmed in one grouped selector. Use stable IDs, sum allocations for group rollups, and never add a group total to its members again. Missing member targets must follow D1's incomplete-plan policy.
- Support YTD, rolling twelve months and custom inclusive month ranges with the agreed anchor; enumerate calendar gaps.
- Category/group choices come from the selected Publication, beyond the current summary month. Invalidated choices reset visibly.
- Retain missing points as gaps, qualified complete-category zero and negative Refunds. An incomplete plan cannot masquerade as a complete total target.
- Isolate Plotly inside one rendering module with explicit cleanup/update behavior on HTMX navigation; no chart-owned report querying or financial aggregation.
- Provide matched accessible title, description, point labels and exact-value table; budget styling must differ from provisional actuals without relying on color alone.

## Testing Decisions

- Known actuals 8700/1900 against target 1500 remain exact; net refund -600 remains negative; these synthetic examples do not prescribe household categories.
- April no-evidence and later confirmed category absence render differently; missing budgets form gaps.
- Controls compose with Publication/accounts/range, invalid ranges are explained, and table values remain usable with chart enhancement unavailable.

Use the agreed public HTTP/rendered-page and analytics-report seams. Each behavior follows one focused red test → maintainer review → green implementation → separate review/refactoring. Use synthetic data and ephemeral test-profile stores; no project-owned collaborator mocks or real bank data. Browser QA uses a separate synthetic development demo, not a served test profile.
