# D2: Build the authenticated dashboard shell and shared navigation

Part of: https://github.com/ATherkel/budget/issues/100. First-release delivery plan.

Blocked by: #101, #12

## Problem Statement

Create the production HTTP shell with real access control and coherent view state, so later display slices do not grow their own authentication, routing and selection rules.

## Solution

One authenticated, responsive shell supports synthetic contexts and intentional error states; focused red/green evidence and quality checks pass.

## User Stories

1. As a household member, I want the same passphrase policy on every page and fragment, so that private reports are protected.
2. As a reader, I want an understandable empty or failed request state, so that absence is not read as zero.
3. As a maintainer, I want an injectable report adapter, so that UI development does not require unfinished import code.

## Implementation Decisions

- Use FastAPI, Jinja and HTMX with a synthetic report adapter satisfying D0; keep Plotly outside this slice.
- Build Danish page shell, Enkel/Avanceret navigation, account/month controls, named historical context and shared errors. Centralize validated Report context and View state.
- Implement the accepted scrypt/passphrase location, HttpOnly/SameSite=Strict sessions, failed-login slowing and logout. First agree session lifetime/invalidation in the acceptance brief; no demo-login bypass.
- Construct allowed reporting dependencies from an explicit Profile. The HTTP module never receives Bronze/Silver paths or creates schema. Real storage startup can wait for D10; refusal behavior cannot.
- Prevent stale partial responses from overwriting newer selections. Empty selection prompts for accounts. Implement browser back/forward behavior through validated state.
- Protect full pages, fragments and report/download surfaces equally; escape report text, exclude financial payloads from logs and configure privacy-conscious response caching.

## Testing Decisions

- Observe login/failure/logout, unauthenticated fragment rejection, explicit empty-selection and invalid-period responses through HTTP.
- Prove Profile validation and that injected synthetic report data is rendered without direct storage access.
- Keyboard focus and phone-width navigation work with ordinary links/forms; HTMX enhances the same public behavior.

Use the agreed public HTTP/rendered-page and analytics-report seams. Each behavior follows one focused red test → maintainer review → green implementation → separate review/refactoring. Use synthetic data and ephemeral test-profile stores; no project-owned collaborator mocks or real bank data. Browser QA uses a separate synthetic development demo, not a served test profile. Astra coordinates; one Flash 4.1 writer implements the approved scope. Run applicable tests and lint/format/types/complexity checks.

## Out of Scope

Financial calculations, real data importing, roles/user management, internet deployment and generic UI frameworks.
