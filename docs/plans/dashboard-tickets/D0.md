## Problem Statement

## User Stories

1. As a maintainer, I want every view to use one validated Report context, so that account, period and Publication selection stay coherent.
2. As a reader, I want uncertainty and errors described consistently, so that unknown amounts cannot masquerade as zero.
3. As an implementer, I want worked report examples, so that the interface can be implemented and tested independently of the UI.

## Implementation Decisions

- Specify requests and typed responses for monthly summary, category/group detail, trends, account activity and public checks, sharing Publication identity, currency, selected accounts, period and explicit reference date.
- Define Decimal/lossless serialization, signed amounts, ratio units, nullable values, Coverage per contributing account-month, provisional reasons and exact reconciliation/count fields. Presentation consumes finished financial values.
- Resolve the public source of late-booking export evidence: analytics needs the admitted export date/range rule, while its Gold access is restricted. Propose the smallest public projection if absent; never reach privileged lineage or Silver.
- Resolve snapshot-versus-latest-dated-balance wording, managed-period/no-data distinctions, taxonomy identifiers, invalid selection states and PublicationUnavailable. Category detail uses allocation identity and amount.
- Record accepted interaction defaults and group/category trend selection from the parent spec. Propose compact route-neutral state transitions, including stale fragment protection and pinned Publications.
- Confirmed defaults: all imported accounts, current Copenhagen month, Enkel on a fresh visit, historical known-at month, and trend ranges anchored to the selected month. Support both Category groups and Categories in one grouped selector, without nested controls. Do not reopen these decisions.
- Provide independent synthetic examples and an architecture/document reconciliation list for #12. The parent spec supersedes old prototype scope notes, not accepted ADRs. An ADR amendment is required where a new contract changes accepted policy.
