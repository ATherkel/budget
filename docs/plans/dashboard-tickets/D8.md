# D8: Add historical Publication navigation and concurrent-read recovery

Part of: https://github.com/ATherkel/budget/issues/100. First-release delivery plan.

Blocked by: #104, #106, #108

## Problem Statement

Make retained historical views navigable and preserve one coherent report context while imports or retention change current data.

## Solution

History and unavailable-result recovery are verified against the accepted public publication adapter. Pinning is not introduced late; this slice verifies and exposes it.

## User Stories

1. As an operator, I want Current, As-was and As-known-at choices, so that historical interpretations are explicit.
2. As a reader, I want a historical banner in both modes, so that I do not mistake an old report for today's state.
3. As a reader, I want a clear recovery when a Publication disappears, so that the app does not silently substitute numbers.

## Implementation Decisions

- Add retained-Publication navigation in Avanceret and a persistent named banner/return-to-current action in both modes.
- Use the selected Publication's knowledge time for historical trust labels and budget identity according to D1; do not merely relabel current data.
- Exercise the context pinning already present since D2/D3 across full pages, HTMX fragments, trend and detail requests under concurrent promotion.
- Handle PublicationUnavailable with an explicit choice to return to current, and explain legacy/unreadable historical results without attempting migrations or builds from the browser.
- Use differing synthetic facts, taxonomy and plans to prove As-was and As-known-at are distinct; historical mode never becomes current through a read.

## Testing Decisions

- Change current Publication between initial render and a fragment request; the original page remains internally coherent.
- Remove a no-longer-retained Publication and verify the response is not a successful report from another one.
- Historical banner survives mode switch, return-to-current is visible, and selected data/plan/reference date agree.

Use the agreed public HTTP/rendered-page and analytics-report seams. Each behavior follows one focused red test → maintainer review → green implementation → separate review/refactoring.
